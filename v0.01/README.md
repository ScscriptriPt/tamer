# 驯兽师 v0

v0 只验证一件事：**每天两条消息，能不能让你的一天有结构**。
没有数据库、没有工具、没有状态机。数据在两个文件里，人工维护，跑三天再决定哪里值得代码化。

## 文件

- `pool.md` —— A 层项目池（长期有哪些事）
- `plan.json` —— 今天的三块（B 层）
- 本文件 —— 规则与消息格式

## 两层结构

- **A 层：项目池。** 不设上限。分主线（有截止、有进度要求）和支线（轻、可中断、探索性）。
- **B 层：当天编排。** 每天从池里抽 **2 个主线 + 1 个支线**，各自占一个时间块。

抽取规则（顺序即优先级，写成规则就是为了不让模型每天自由发挥）：

1. **截止日期优先。** 30 天内到期的项目必须占据主块，直到风险解除。
2. **同一项目连续不超过 2 天。** 第三天必须换手，防止单线程死磕。
3. **支线每天只准一个**，且优先选「已经开了头、还没收尾」的，不选新的。
4. 每天最多 3 块。块数只能减不能加。

## 默认骨架

```
09:00–10:30   主线一
10:45–11:45   主线二
14:00–15:00   支线
21:30         回扣
```

下午到晚上留白。**留白是设计**，你塞满了第三天就崩。

## 消息格式（早 8:30）

```markdown
早。今天三块：

**09:00–10:30** 主线一 —— 《项目名》下一步：<一句话动作>
**10:45–11:45** 主线二 —— 《项目名》下一步：<一句话动作>
**14:00–15:00** 支线 —— 《项目名》下一步：<一句话动作>

搁置中：<2–3 条，带唤醒日期>
今天不要做：<2–3 条，具体到动作>

<块一结束前要留的话：一句断点>
```

硬约束：

- 不超过 10 行。
- 不写鼓励、不写总结、不写「加油」。
- 每条「下一步」必须是一个能在 90 分钟内开始的动作，不是「学习 X」这种词。
- 「今天不要做」必须具体到动作（「换笔记软件」可以，「保持专注」不行）。

## 消息格式（晚 21:30）

一次只问一个问题，问完等回答：

1. 今天三块里，哪块真做了？
2. 没做的那块，断在哪？下一块开始时的第一个动作是什么？

答完写回 `plan.json` 的 `result`，然后结束对话，不要展开说教。

## 例外日

出去玩、考试、生病、状态崩：当天记 `"day_type": "exception"`。
不生成计划、晚上不问验收、第二天不补昨天的债、不累计欠账。

**这条是硬规则。** 任何让你产生「我欠了三天」的机制，最后都会被关掉。

## 定时

两条 ds-bot 定时提醒（08:30 / 21:30）挂在当前会话上。触发时执行 CLI，不再直接读 `plan.json`：

```
node core/src/cli.ts plan render --morning --date <今天>
node core/src/cli.ts plan review --date <今天> --block N --done|--undone --note "..."
node core/src/cli.ts plan breakpoint --date <今天> --block N --did "..." --next "..."
```

调整时间或取消：`schedule_list` 查看 id，`schedule_update` / `schedule_delete`。

## 数据纪律

`data/` 是真实数据，**任何演示、验收、试跑都不得写入**。

- 演示和端到端验收一律用 `--data-dir` 指向临时目录，跑完删掉。
- 测试只读写自己创建的临时目录。
- 违反这条的后果很具体：一个假断点会让第二天早上那条消息直接失真。
