# 规格：初始化（onboarding）

> 现状：空目录下 `idea add` 报「无法读取文件」，`plan new` 报同样的错。
> 对别人来说这不是边缘 bug，是**第一条命令就失败**——`data/` 在 `.gitignore` 里，克隆下来就是空的。

## 1. 目标

在一台什么都没有的机器上，三条命令能跑通：

```
node core/src/cli.ts init
node core/src/cli.ts idea add "想试试 nvim"
node core/src/cli.ts plan new --date 2026-10-23
```

## 2. `init` 命令

```
node core/src/cli.ts init [--data-dir <dir>]
```

行为：

- 创建数据目录（含父目录，已存在则复用）
- 写入 `pool.json`：`{"version":1,"projects":[]}`
- 写入 `ideas.json`：`{"version":1,"ideas":[]}`
- **绝不覆盖已有文件。** 已存在就跳过，stderr 提示 `已存在，跳过：<路径>`，退出码仍为 0
- 结束时打印一行：`已初始化：<目录>`，并列出创建/跳过了哪些文件

## 3. 写入路径容错

`idea add / wake / promote / discard`、`plan review / breakpoint`：

- 目标文件**不存在** → 按空数据起步，正常写入
- 文件存在但**JSON 损坏或结构非法** → 必须报错，退出码 1。**容错不等于吞错**

## 4. `plan new` 的前置检查

`pool.json` 不存在时：

- 退出码 1
- stderr：`没有项目池。先跑：node core/src/cli.ts init`
- 不要自动创建空池（空池排出来的"零块计划"看起来像成功，实际是误导）

## 5. 测试（≥6 条）

1. 空目录 `init` → 两个文件都在，内容为空书
2. `init` 重复跑 → 不覆盖，退出码 0，原有数据不变（用已有项目的池验证字节不变）
3. 空目录 `idea add` → 成功，`ideas.json` 被创建，`occurrences = 1`
4. 空目录 `plan new` → 退出码 1，stderr 含「init」
5. `init` 后 `plan new` → 退出码 0，生成 0–1 块不报错
6. `ideas.json` 内容为 `{`（损坏）→ `idea add` 退出码 1，文件内容**不被改写**
7. 所有写入路径都在临时目录里测，不碰真实 `data/`

## 6. 边界

- 零依赖，不改 `v0.01/`、`vendor/`、根目录 md
- 不 git 操作
- 不加新依赖、不改 R1–R8 的语义
