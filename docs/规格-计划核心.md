# 规格：确定性计划核心（v0.01，历史）

> 目的：把「今天该做什么」从**模型自由发挥**变成**规则产出**。
> 这一版不含 LLM、不含 MCP、不含任何宿主集成，只是一段能在本机跑、有测试的 TypeScript 核心。

## 1. 目标

给定一个项目池和日期，产出当天的三块编排，并渲染出两条消息的文本。

## 2. 非目标

- 不接 MCP、不接 ds-bot、不调用任何模型 API
- 不做 UI、不做 TUI
- 不做推送（推送由外部定时器负责）
- 不做多用户、不做云同步

## 4. 数据模型

### `data/pool.json`

```json
{
  "version": 1,
  "projects": [
    {
      "id": "microwave",
      "title": "微波技术",
      "kind": "main",
      "status": "active",
      "deadline": "2026-10-26",
      "wake_at": null,
      "last_touched": "2026-10-22",
      "progress": 0,
      "note": "从零开始，10-26 期中"
    }
  ]
}
```

- `kind`: `main` | `side`
- `status`: `active` | `paused` | `shelved` | `done`
- `deadline` / `wake_at`: `YYYY-MM-DD` 或 `null`
- `progress`: `0`–`1`，未知填 `null`

### `data/plans/YYYY-MM-DD.json`

```json
{
  "date": "2026-10-23",
  "day_type": "normal",
  "blocks": [
    {
      "start": "09:00",
      "end": "10:30",
      "kind": "main",
      "project_id": "microwave",
      "action": "划范围：翻目录和往年卷，产出一页 4 天路线图",
      "done_when": "那页路线图存在，每章后面标了小时数",
      "breakpoint": null
    }
  ],
  "shelved": [{ "project_id": "notion-migrate", "reason": "考试周不碰，10-27 恢复" }],
  "do_not": ["换笔记软件", "开任何新项目"],
  "risk": null,
  "result": null
}
```

- `day_type`: `normal` | `exception`
- `action` / `done_when` 由**调用方传入**或由项目 `note` 兜底；核心不负责编造文案
- `result` 结构：`{ "reviewed_at": "...", "blocks": [{ "project_id": "...", "done": true, "note": "..." }] }`

### `data/ideas.json`

```json
{
  "version": 1,
  "ideas": [
    {
      "id": "idea-20261022-1",
      "text": "想试试 nvim",
      "captured_at": "2026-10-22",
      "state": "graveyard",
      "occurrences": 1,
      "wake_at": null,
      "reason": null
    }
  ]
}
```

- `state`: `graveyard` | `explore` | `wake` | `promoted` | `discarded`
- `occurrences` 是代码记的数，不是模型判断的；同一个想法重复出现由调用方自增

## 5. 规则（必须实现为纯函数，每条都有测试）

按顺序求值，前一条命中即决定该块。

- **R1 截止优先**：`status=active`、`kind=main`、`deadline` 在 30 天内（含今天）的项目，按 `deadline` 升序优先入选。
- **R1a 高危独占**：某 main 项目 `deadline` 距今天 ≤ 7 天时，允许占 **2 个** main 块；否则每个项目最多占 1 块。
- **R2 连续限制**：同一 `project_id` 连续 2 天出现在 `blocks` 中，第 3 天不再选它；除非它命中 R1a 且无替代，此时允许但必须在 `plan.risk` 里追加一句 `forced: <project_id>`。
- **R3 第二主线**：main 块还有空位时，从剩余 active main 里选 `last_touched` 最早（最久没动）的；`last_touched` 为空视为最早，同为空按 `pool.json` 里的顺序。
- **R4 支线**：恰好 1 个 side 块。优先选 `progress` 在 `(0,1)` 之间且 `last_touched` 最近的（开了头没收尾）；没有则选 `last_touched` 最早的 active side；都没有则留空，不报错。
- **R5 例外日**：`day_type=exception` 时不出 `blocks`，`renderMorning` 返回空字符串，`review` 返回 `null`。
- **R6 块数**：`blocks.length <= 3`，无可用项目时允许 0–2 块，不得报错。

## 6. 渲染

`renderMorning(plan, pool)`：严格照 `core/test/render.test.ts` 锁定的早间格式，**不超过 10 行**，无鼓励语、无总结句。
`renderEvening(plan, step)`：`step=1` 问「今天三块里，哪块真做了」；`step=2` 问「没做的那块断在哪，下一块的第一个动作是什么」。只输出这一个问题。

渲染必须是确定性的：同样输入，逐字节相同。

## 7. CLI

```
node core/src/cli.ts plan new --date 2026-10-24
node core/src/cli.ts plan show --date 2026-10-24
node core/src/cli.ts plan render --morning --date 2026-10-24
node core/src/cli.ts plan render --evening --step 1 --date 2026-10-24
node core/src/cli.ts plan review --date 2026-10-23 --block 1 --done --note "做完了"
node core/src/cli.ts idea add "想试试 nvim"
node core/src/cli.ts idea list
```

`plan new` 对已存在且 `result != null` 的计划必须**拒绝覆盖**并退出码 2。
