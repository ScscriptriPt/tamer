# 规格：想法分流（v0.03，历史）

> 治第一个失控模式：被新想法带走。
> 这一版只做**记账与门槛**，不做语义判断——"这是不是同一个想法"由模型判，代码只认命令。

## 1. 非目标

- 不做语义去重（模型判断后传 `--same <id>`）
- 不做周末探索预算（需要周维度，v0.04）
- 不改 R1–R7

## 2. CLI

```
node core/src/cli.ts idea add "<text>" [--same <id>] [--wake 7|30|YYYY-MM-DD]
node core/src/cli.ts idea list [--state graveyard|explore|wake|promoted|discarded] [--due]
node core/src/cli.ts idea wake <id> --at YYYY-MM-DD
node core/src/cli.ts idea promote <id> --next "<一句话动作>" [--kind main|side] [--deadline YYYY-MM-DD]
node core/src/cli.ts idea discard <id> --reason "<一句话>"
```

- `idea add` 不带 `--same`：新想法，`occurrences = 1`，`id = idea-<YYYYMMDD>-<n>`，n 当天递增
- `idea add --same <id>`：同一条的 `occurrences += 1`，`text` 不覆盖，`captured_at` 不变
- `--wake 7` / `--wake 30`：相对今天；`--wake 2026-11-01`：绝对日期。同时把 `state` 置为 `wake`
- `idea list --due`：列出 `state = wake` 且 `wake_at <= today` 的条目

## 3. 规则（纯函数）

- **R8 三次门槛**：`promote` 要求 `occurrences >= 3`，否则退出码 **3**，stderr 输出 `还差 <N> 次才能升级`。
- **R9 名额**：`promote` 时检查 `pool.json` 里 `status = active` 的数量——**主线不限**（每天只抽两门排块），**支线 ≤ 2**。支线满了退出码 **4**，stderr 提示先 `discard` 或替换现有项目。被 promote 的项目 `status = active`，`id` 复用 idea 的 id。
- **R10 到期**：`due` 的口径是 `wake_at <= today`，闭区间，字符串比较即可。
- **R11 状态机**：非法迁移报错退出码 1。合法路径：`graveyard → wake`、`wake → promoted`、`wake → discarded`、`graveyard → promoted`、`graveyard → discarded`、`promoted → done`（由项目层处理，不在本版）。

## 4. 渲染

早间消息**末尾**追加一行，仅当有到期项：

```
到期唤醒：想试试 nvim（7 天前）
```

- 最多列 3 条，逗号分隔
- 没有到期项时**不追加任何行**（快照测试必须逐字节不变）
- 消息总行数仍不超过 10

## 5. 测试（≥6 条）

1. 同一条 add 三次 → `occurrences = 3`，id 不变
2. 两次就 `promote` → 退出码 3，stderr 含"还差 1 次"
3. 支线已有 2 个 active 时 promote 支线 → 退出码 4；主线已有 5 个 active 时 promote 第 6 个主线仍成功
4. `--wake 7` 写入的日期等于今天 +7
5. `due` 只返回已到期且 `state = wake` 的
6. 无到期项时早间消息快照与 v0.02 完全一致

## 6. 验收

- `node --test core/test` 全绿
- 用 `--data-dir <临时目录>` 演示完整链路：add ×3 → promote → 出现在 `pool.json` 里，贴输出
- **不许污染 `data/`**

## 7. 边界

- 零依赖，不改 `vendor/`、根目录 md，不 git init
- 核心函数不读时钟，`today` 由 CLI 传入
